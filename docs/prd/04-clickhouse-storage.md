# ClickHouse 적재

- 상태: 초안
- 적용 범위: 제품 v1

## 목표

변환된 주문 데이터를 ClickHouse에 적재하고 조회한다.

## 범위 및 후속 정의 사항

테이블 구조, 적재 실패 및 중복 처리, 조회 검증 기준을 이 단계에서 정의한다.

## 처리지연 측정

[공통 측정 원칙](01-log-generator.md#공통-측정-원칙)을 따른다. INSERT 응답과 실제 조회 가능 시점을 구분한다.

| 기준점·지표 | 기록 위치·계산 | 의미 |
| --- | --- | --- |
| INSERT 시작·완료 | 클라이언트의 실제 INSERT 요청 직전·성공 응답 직후 | 단조 증가 시계 차이로 전송·서버 처리·응답 소요시간 측정 |
| 최초 조회 확인 (`first_observed_at`) | 검증용 조회 결과에서 샘플 이벤트를 처음 발견한 시각 | 조회 가능 시각의 관측 상한이며 내부 저장 완료 시각과 다름 |
| 생성 → 조회 가능 지연 | `first_observed_at - event_timestamp` | 파이프라인 전체 데이터 지연의 관측값 |

- 적재 방식과 응답의 성공 의미를 명시한다. 비동기 INSERT는 큐 수락만 확인하는지 실제 flush 완료까지 기다리는지 설정을 함께 기록한다. 분산 테이블을 사용하면 실제 대시보드 조회 경로에서 확인한다.
- 배치별 쓰기 지표에 Spark 실행·배치 ID, 시도 번호, 건수, 실패와 재시도를 기록한다. 성공 응답 시각은 응답 후에 알 수 있으므로 이미 보낸 행에 저장하지 않고 별도 운영 지표로 관리한다.
- `event_timestamp`, Kafka 추가 시각·topic·partition·offset, Spark 배치 식별자를 후속 컬럼으로 보존한다. 서버 기본값으로 생성한 적재 시각은 평가 시점을 명시하며 INSERT 완료·조회 가능 시각으로 간주하지 않는다.
- 정상 주문의 `event_id`를 샘플링해 주기적으로 조회한다. 최초 발견 시각, 조회 주기·소요시간·샘플 수·미발견 수·타임아웃을 기록한다. 조회 주기와 조회 소요시간이 지연 관측값에 포함됨을 표시한다.
- 재시도나 items 분리로 같은 이벤트가 여러 행에 있어도 최초 관측은 이벤트당 한 번만 집계한다. 불량 격리 경로의 지연은 정상 주문 적재와 별도로 관리한다.

## 완료 기준

해당 단계에 착수할 때 지연 목표값·측정 구간·샘플링 설정을 포함한 정량 기준을 확정한다. 아래 계측은 요구사항이며 아직 구현·검증하지 않았다.

INSERT 성공 의미와 조회 경로를 확인하고, 샘플 이벤트 최초 관측·미발견·중복 제거·조회 오차 기록을 검증한다. 쓰기 지연과 적재 실패를 각각 주입해 확인한다.
